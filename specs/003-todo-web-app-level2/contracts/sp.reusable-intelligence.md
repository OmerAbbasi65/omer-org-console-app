# Reusable Intelligence Specification: Level 2 (Organization)

**Phase**: Phase 2 - Level 2 (Organization Features)
**Date**: 2026-01-09

## Overview

This document defines reusable intelligence artifacts for Level 2 (Organization) features, including specialized subagents and agent skills that can be leveraged across the development lifecycle.

---

## Subagent Definitions

### 1. Database Query Optimizer Agent

**Purpose**: Analyze and optimize database queries for filter, search, and sort operations

**Responsibility**:
- Review SQL queries generated by SQLModel/SQLAlchemy
- Identify missing or inefficient indexes
- Suggest query optimizations for performance
- Validate EXPLAIN ANALYZE output

**Inputs**:
```typescript
{
  query: string,              // SQL query text
  explainPlan?: string,       // EXPLAIN ANALYZE output (optional)
  taskCount: number,          // Number of tasks in database
  filters?: {                 // Applied filters
    priority?: string,
    tags?: string[],
    status?: string
  },
  sortBy?: string
}
```

**Outputs**:
```typescript
{
  optimizationSuggestions: [
    {
      issue: string,          // Description of performance issue
      suggestion: string,     // Recommended optimization
      priority: "high" | "medium" | "low",
      estimatedImprovement: string  // e.g., "50% faster"
    }
  ],
  missingIndexes: string[],   // Index creation suggestions
  queryScore: number          // 0-100, higher is better
}
```

**Example Usage**:
- Developer writes complex filter query
- Runs query through optimizer agent
- Agent identifies missing GIN index on tags
- Developer adds index, re-runs query, performance improves

**Reusability**: Can be used for Level 3 (due dates, recurring tasks) query optimization

### 2. Tag Normalization Agent

**Purpose**: Standardize and deduplicate tags across tasks

**Responsibility**:
- Analyze tag usage across all tasks
- Identify near-duplicate tags (typos, plurals, case variations)
- Suggest tag merges and renames
- Generate tag taxonomy

**Inputs**:
```typescript
{
  allTags: string[],          // All unique tags in database
  taskCounts: {               // Number of tasks per tag
    [tag: string]: number
  },
  caseSensitive: boolean      // Whether to treat "Work" and "work" as different
}
```

**Outputs**:
```typescript
{
  duplicates: [
    {
      canonical: string,      // Suggested canonical tag
      variants: string[],     // Similar tags to merge
      taskCount: number       // Total tasks across variants
    }
  ],
  taxonomy: {
    categories: string[],     // Suggested top-level categories
    subcategories: {
      [category: string]: string[]
    }
  },
  unusedTags: string[]        // Tags with 0 tasks (orphaned)
}
```

**Example Usage**:
- User has tags: "work", "Work", "urgent", "Urgent", "urgnet" (typo)
- Agent suggests: merge "Work" → "work", merge "Urgent" → "urgent", rename "urgnet" → "urgent"
- Developer creates migration script to update tags

**Reusability**: Can be extended for hierarchical tags in Level 3+

### 3. Filter Query Builder Agent

**Purpose**: Generate optimized SQL queries for complex filter combinations

**Responsibility**:
- Convert filter state to efficient SQL WHERE clauses
- Handle composite filters (multiple priorities, tags, status)
- Optimize for index usage
- Generate human-readable query explanations

**Inputs**:
```typescript
{
  filters: {
    status?: "completed" | "incomplete",
    priority?: "high" | "medium" | "low" | "none",
    tags?: string[],          // AND logic (task must have all tags)
    search?: string
  },
  sortBy?: "priority" | "title" | "createdAt" | "updatedAt",
  sortOrder?: "asc" | "desc"
}
```

**Outputs**:
```typescript
{
  sqlQuery: string,           // Generated SQL WHERE clause
  parameters: any[],          // Parameterized query values
  indexesUsed: string[],      // Indexes that will be used
  estimatedRows: number,      // Expected result count
  explanation: string         // Human-readable query description
}
```

**Example Usage**:
- User selects: status=incomplete, priority=high, tags=["work", "urgent"]
- Agent generates:
  ```sql
  WHERE completed = false
    AND priority = 'high'
    AND tags @> ARRAY['work', 'urgent']::text[]
  ORDER BY created_at DESC
  ```
- Explanation: "Showing incomplete high-priority tasks tagged with both 'work' and 'urgent', sorted by creation date (newest first)"

**Reusability**: Can be extended for Level 3 date-based filters (overdue, due today, etc.)

### 4. Search Relevance Ranker Agent

**Purpose**: Improve search result quality by ranking matches

**Responsibility**:
- Analyze search query and task content
- Assign relevance scores to matching tasks
- Rank results by relevance (not just chronological)
- Handle partial matches and typos

**Inputs**:
```typescript
{
  searchQuery: string,        // User's search term
  tasks: [
    {
      id: string,
      title: string,
      description: string,
      tags: string[]
    }
  ]
}
```

**Outputs**:
```typescript
{
  rankedTasks: [
    {
      taskId: string,
      relevanceScore: number,  // 0-100
      matchedFields: string[], // ["title", "description", "tags"]
      snippet: string          // Highlighted excerpt
    }
  ],
  totalMatches: number
}
```

**Ranking Algorithm**:
1. Exact title match: score = 100
2. Title contains query: score = 80
3. Description contains query: score = 60
4. Tag matches query: score = 40
5. Partial match (fuzzy): score = 20

**Example Usage**:
- User searches "deploy app"
- Agent ranks:
  1. "Deploy application" (title exact) - score: 100
  2. "Deploy app to staging" (title contains) - score: 80
  3. "Prepare deployment" (title partial) - score: 60
  4. Task with tag "deployment" - score: 40

**Reusability**: Can be extended with TF-IDF or semantic search in Level 3+

## Agent Skills

### Skill 1: Priority Inference

**Purpose**: Suggest task priority based on title and description keywords

**Input Schema**:
```typescript
{
  title: string,
  description?: string
}
```

**Output Schema**:
```typescript
{
  suggestedPriority: "high" | "medium" | "low" | null,
  confidence: number,        // 0-1 (0.8 = 80% confident)
  reasoning: string          // Why this priority was suggested
}
```

**Inference Rules**:
- Keywords "urgent", "critical", "asap", "emergency" → high (confidence: 0.9)
- Keywords "important", "should", "need" → medium (confidence: 0.7)
- Keywords "someday", "maybe", "consider" → low (confidence: 0.7)
- No keywords → null (confidence: 0.5)

**Example**:
- Input: `{title: "Fix critical bug in production", description: "Urgent - users can't login"}`
- Output: `{suggestedPriority: "high", confidence: 0.95, reasoning: "Contains 'critical' and 'urgent'"}`

**Reusability**: Can be trained with ML in Level 3+ for better accuracy

### Skill 2: Tag Suggestion

**Purpose**: Suggest relevant tags based on task content and existing tag corpus

**Input Schema**:
```typescript
{
  title: string,
  description?: string,
  existingTags: string[]      // All tags in database (for consistency)
}
```

**Output Schema**:
```typescript
{
  suggestedTags: [
    {
      tag: string,
      confidence: number,      // 0-1
      reason: string           // Why suggested
    }
  ]
}
```

**Suggestion Rules**:
- Extract nouns from title/description
- Match against existing tags (prefer reuse over new tags)
- Suggest max 5 tags
- Confidence based on word frequency and context

**Example**:
- Input: `{title: "Deploy application to production", existingTags: ["work", "deployment", "urgent"]}`
- Output:
  ```typescript
  {
    suggestedTags: [
      {tag: "deployment", confidence: 0.9, reason: "Exact match in title"},
      {tag: "work", confidence: 0.7, reason: "Common tag for this type of task"}
    ]
  }
  ```

**Reusability**: Can evolve into full NLP-based tag extraction in Level 3+

### Skill 3: Duplicate Task Detector

**Purpose**: Identify potential duplicate or similar tasks

**Input Schema**:
```typescript
{
  newTask: {
    title: string,
    description?: string
  },
  existingTasks: [
    {
      id: string,
      title: string,
      description?: string,
      completed: boolean
    }
  ]
}
```

**Output Schema**:
```typescript
{
  potentialDuplicates: [
    {
      taskId: string,
      similarityScore: number,  // 0-1 (0.9 = 90% similar)
      reason: string
    }
  ],
  isDuplicate: boolean          // True if similarity > 0.85
}
```

**Similarity Algorithm**:
1. Exact title match: 1.0
2. Levenshtein distance (edit distance)
3. Jaccard similarity (word overlap)
4. Consider tags if available

**Example**:
- New task: "Buy groceries"
- Existing task: "Buy grocery items"
- Output: `{similarityScore: 0.88, isDuplicate: true, reason: "Very similar title"}`

**Reusability**: Prevents duplicate task creation, improves data quality

### Skill 4: Bulk Tag Editor

**Purpose**: Apply tag operations to multiple tasks in batch

**Input Schema**:
```typescript
{
  taskIds: string[],          // Tasks to modify
  operation: "add" | "remove" | "replace",
  tags: string[]              // Tags to add/remove/replace
}
```

**Output Schema**:
```typescript
{
  modifiedTasks: number,      // Count of tasks updated
  errors: [
    {
      taskId: string,
      error: string
    }
  ],
  summary: string             // Human-readable summary
}
```

**Operations**:
- **Add**: Append tags to existing tags (deduplicate)
- **Remove**: Remove specified tags from existing tags
- **Replace**: Replace all tags with new set

**Example**:
- Input: `{taskIds: ["task-1", "task-2"], operation: "add", tags: ["urgent"]}`
- Output: `{modifiedTasks: 2, errors: [], summary: "Added tag 'urgent' to 2 tasks"}`

**Reusability**: Useful for managing tasks at scale (Level 2+)

## Intelligence Versioning

### Versioning Rules

**Agent Versions**:
- Format: `v{major}.{minor}` (e.g., `v1.0`)
- Major version bump: Breaking changes to inputs/outputs
- Minor version bump: New features, backward-compatible

**Skill Versions**:
- Format: `v{major}.{minor}.{patch}` (e.g., `v1.2.1`)
- Major: Breaking changes
- Minor: New features
- Patch: Bug fixes, improved accuracy

### Version Tracking

Store agent/skill versions in code:

```typescript
// agents/database-optimizer.ts
export const VERSION = "v1.0";
export const LAST_UPDATED = "2026-01-09";
```

### Deprecation Policy

**Deprecated Agents/Skills**:
- Mark as deprecated 6 months before removal
- Provide migration guide
- Log warnings when deprecated versions are used

## Reusability Constraints

### When to Create New Agent vs. Skill

**Agent**:
- Complex, multi-step reasoning
- Requires access to database or external APIs
- Stateful (maintains context across calls)
- Example: Database Query Optimizer

**Skill**:
- Single-purpose, deterministic function
- Operates on provided data only (no external dependencies)
- Stateless (pure function)
- Example: Priority Inference

### Cross-Level Reusability

**Level 2 → Level 3**:
- All Level 2 agents/skills MUST work in Level 3
- Level 3 can extend Level 2 agents (subclass or compose)
- No breaking changes to Level 2 intelligence

**Example**:
- Level 2: Tag Suggestion (basic keyword matching)
- Level 3: Enhanced Tag Suggestion (ML-based, learns from user behavior)
- Level 3 extends Level 2 skill, falls back to keyword matching if ML unavailable

## Testing Intelligence

### Unit Tests for Skills

**Required Tests**:
- All input variations (valid, invalid, edge cases)
- Output format validation (matches schema)
- Performance (< 100ms for deterministic skills)

**Example Test (Priority Inference)**:
```typescript
test('Priority Inference - urgent keyword', () => {
  const result = inferPriority({
    title: "URGENT: Fix production bug",
    description: "Critical issue"
  });

  expect(result.suggestedPriority).toBe("high");
  expect(result.confidence).toBeGreaterThan(0.8);
  expect(result.reasoning).toContain("urgent");
});
```

### Integration Tests for Agents

**Required Tests**:
- Agent with real database connection
- Agent with mock data (for speed)
- Error handling (database down, timeout)

**Example Test (Database Query Optimizer)**:
```typescript
test('Query Optimizer - suggests GIN index for tags', async () => {
  const result = await optimizeQuery({
    query: "SELECT * FROM tasks WHERE tags @> ARRAY['work']",
    taskCount: 10000
  });

  expect(result.missingIndexes).toContain("idx_tasks_tags (GIN)");
  expect(result.queryScore).toBeLessThan(60); // Poor without index
});
```
